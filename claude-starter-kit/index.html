1. Modelo mental

Chat
Interação curta e iterativa: argumento, resumo, revisão, redação.
Cowork / Claude
Tarefa multi-step: cruzar arquivos, chronology, dossiers, deliverables.
Claude Code
Automação técnica, lotes de arquivos, scripts. Aprenda depois.
Regra: Claude é camada de análise e execução. Não é o repositório oficial do caso.
DMS oficial→working set→Claude Project→output revisado→DMS

2. Setup inicial

  1. Claude Desktop atualizado e workspace Team correto.
  2. Global Instructions curtas.
  3. 1 Project por matter; nunca misturar clientes.
  4. Project Instructions com partes, instituição/foro, lei, idioma, estágio, citation rules.
  5. Pasta 05_CLAUDE no working copy do matter.
  6. Começar com 4 skills: Onboarding, Chronology, Pleading Red Team e Session Closeout.
Sou advogada de contencioso complexo e arbitragem.

Priorize precisão sobre fluência. Nunca invente fatos, autoridades, citações, números de processo ou fontes.

Separe:
FACT = suportado por fonte;
ALLEGATION = afirmação de parte/testemunha;
INFERENCE = conclusão analítica;
UNKNOWN = não estabelecido.

Para fatos materiais, cite documento e página/seção quando possível.
Se a fonte não provar exatamente a proposição, diga isso.
Em research, prefira fonte primária e marque o que não foi verificado.
Ao revisar nossa posição, procure também fatos e argumentos contrários.
Outputs jurídicos são first drafts sujeitos a revisão humana.
Windows-specific

3. Setup no Windows

⊞
Para a Verena, Windows muda a configuração — não a metodologia.

Claude Desktop, Chat, Cowork e Claude Code funcionam no Windows. O ponto importante é preparar corretamente o PC para Cowork e manter o acesso a arquivos estritamente limitado às pastas do matter.

SistemaWindows 10 ou superior
AppClaude Desktop atualizado
Cowork localVirtual Machine Platform
PermissãoAdmin para instalação completa

Checklist de instalação

  1. Instale a versão mais recente do Claude Desktop para Windows.
  2. Se Cowork não aparecer ou não conseguir trabalhar com arquivos locais, confirme com TI que a Virtual Machine Platform do Windows está habilitada.
  3. Em instalação individual, o suporte completo ao Cowork no desktop requer privilégios de administrador. Em notebook corporativo bloqueado, peça ao TI para instalar/implantar o app.
  4. Crie uma pasta dedicada de trabalho do Claude — por exemplo C:\Legal\Claude-Working-Sets\ — em vez de conceder acesso amplo a Documents, OneDrive inteiro ou pastas de todos os clientes.
  5. Se o DMS sincroniza localmente via OneDrive/SharePoint, não trate a pasta sincronizada inteira como working set. Exponha somente os arquivos necessários para a tarefa.

Padrão de caminho no Windows

C:\Legal\Matters\MATTER-CLIENT-SHORTNAME\
├── 00_ADMIN\
├── 01_CORE_RECORD\
├── 02_EVIDENCE\
├── 03_RESEARCH\
├── 04_WORK_PRODUCT\
├── 05_CLAUDE\
│   ├── PROJECT_CORE_PACK\
│   ├── SESSION_PACKS\
│   ├── OUTPUTS\
│   └── SESSION_LOG\
└── 99_ARCHIVE\

Team: uma limitação importante

Cowork ≠ “controle total do computador”. No Claude Team, ela pode usar Cowork e trabalhar com arquivos locais conectados. Porém o recurso de computer use que controla outros aplicativos pela interface gráfica continua indisponível para Team no momento. Portanto, não conte com Claude clicando livremente em Word, Outlook ou sistemas do escritório como parte do workflow padrão.

Browser e Chrome

No Team, controles de browser para Cowork existem e a Anthropic está disponibilizando um navegador integrado no Desktop, além da opção Claude in Chrome conforme configuração da organização. Para trabalho jurídico, a regra continua sendo menor privilégio: dê acesso somente quando a tarefa realmente exigir web ou um sistema específico.

Core Pack persistente

Não subir: cada minuta, cada e-mail, o data room inteiro ou versões superseded “por via das dúvidas”.

5. Session protocol

Cada sessão relevante começa com um Session Brief e termina com Session Closeout.

TASK:
DECISION / DELIVERABLE I NEED:

DO NOT USE:
KNOWN FACTS / ASSUMPTIONS:
OPEN QUESTIONS:
OUTPUT FORMAT:
PROCEDURAL CONTEXT:

Before starting, list the working set you actually read.
At the end, run the Session Closeout skill.

6. Versionamento

Nunca: “atualize a última versão”. Sempre nomeie a source version.
StatusRegra
WORKINGEditável, sempre gerando versão nova.
APPROVEDNova alteração = nova versão.
FILED / SIGNEDImutável; leitura apenas.
SUPERSEDEDNão usar salvo instrução expressa.
2026-09-29_Memorial_Claimant_v08_WORKING.docx
2026-09-30_Memorial_Claimant_v09_APPROVED.docx
2026-10-01_Memorial_Claimant_FILED.pdf

Redline: preserve sempre base + redline + clean. O Session Log registra a versão usada.

7. Privacidade — Claude for Teams

Teams é produto comercial: a Anthropic informa que inputs/outputs não são usados para treinamento por padrão; a organização é a controladora e a Anthropic atua como processadora. Owners do workspace podem administrar/exportar dados.

Bom
É muito mais defensável para trabalho corporativo que uma conta consumer.
Mas
Não elimina confidentiality, privilege, LGPD/GDPR, client terms ou regras arbitrais.

Regras práticas

  • Documentos de cliente só se a política do escritório/cliente permitir.
  • Minimize o working set, sobretudo para privilege, segredo comercial e dados sensíveis.
  • Não usar feedback thumbs up/down em conversa confidencial sem saber a política: feedback enviado pode ser usado para melhoria/treinamento.
  • Conectores, browser e MCP: menor permissão possível.
  • Project sharing apenas para o case team.
  • Incognito não substitui governança; em Team, ainda há retenção e possibilidade de export organizacional.

10. Skills prontas

Use como prompt normal ou transforme em Skill no Claude.

01 — Matter Onboarding / Case Map
Act as a senior disputes associate onboarding onto this matter.
Read only the materials supplied. Separate FACT, ALLEGATION, INFERENCE and UNKNOWN. Never fill gaps by assumption. Cite every material factual proposition. Flag contradictions and missing documents.

Output:
A. Executive case snapshot
B. Parties/counsel/tribunal/institution
C. Claims and defenses
D. Key contractual provisions
E. Procedural posture
F. Issue map
G. 20-event core chronology
H. Witness/expert map
I. Key documents
J. Open questions/evidence gaps
K. Immediate next actions
End with Confidence & Verification.
02 — Evidence-Backed Chronology
Build a chronology from the supplied working set.
Do not treat pleadings as proof. Prefer contemporaneous documents. Deduplicate events. Distinguish event date from document date. Cite every row.

Table: Date | Event | Actors | Source | Evidence status | Issue | Helps/hurts/neutral | Notes.
Evidence status: DOCUMENTED / ALLEGED / INFERRED / DISPUTED.
Then list chronology gaps, conflicting dates, corroboration needs, and documents to search next.
03 — Pleading Red Team
Review the draft first as hostile opposing counsel, then as a skeptical tribunal. Do not rewrite immediately.
Pass 1: structure and logic.
Pass 2: factual assertions with weak/missing/mismatched support.
Pass 3: strongest counterarguments, adverse facts, legal/causal leaps.
Pass 4: tribunal questions and unproven points.

Output: Priority | Section | Problem | Why it matters | Counterargument | Recommended fix.
Only then give targeted drafting suggestions.
04 — Witness Preparation
Prepare a witness interview using only the supplied documents.
Create: role, personal chronology, authored/received docs, decisions/meetings, facts within personal knowledge, facts outside it, inconsistencies, adverse documents, corroboration needs, interview questions.
For every question give objective, source and type (open / confirmatory / challenge).
Never fabricate memory or suggest language the witness should adopt.
05 — Cross-Examination Builder
Compare the witness statement against contemporaneous documents, pleadings and other witness evidence.
Identify contradictions, changed stories, unsupported assertions, omissions, inconsistent documents and concessions.
For each cross point: proposition; foundation; document/prior statement; leading-question sequence; exit point; rehabilitation risk; recommendation USE / RESERVE / DROP.
06 — Document Production / Redfern
For each document request assess: issue, relevance/materiality, scope, date range, custodians/repositories, burden/proportionality, privilege/confidentiality, ambiguity, objections and narrower formulation.
Output: Request | Issue | Relevance | Scope risk | Objection candidates | Search plan | Missing info.
For received production identify satisfied, partial, unexplained gaps, missing attachments/referenced docs and incomplete document families.
07 — Verifiable Legal Research
Never invent authorities, quotations, pincites, docket numbers or publication details. Prefer primary sources. State jurisdiction, time and procedural context. Mark inaccessible authorities UNVERIFIED.
Output:
1. Research question
2. Governing framework
3. Proposition | Authority | Court/tribunal | Date | Pinpoint | Primary/secondary | Source | Verified?
4. Conflicting authority
5. Open issues
6. Suggested searches
7. Short answer + confidence.
Check every quotation against the original.
08 — Hearing Daily Digest
Analyze today's transcript and hearing notes.
Produce: executive summary; admissions/concessions; contradictions; tribunal questions; undertakings; evidence gaps; closing points; witness-by-witness record assessment; next-day actions.
Cite transcript page/line.
Maintain Admissions Ledger: Witness | Proposition | Transcript cite | Exhibit | Issue | Follow-up | Status.
09 — Claim / Defense Argument Map
For each claim/defense identify:
legal test/elements; Claimant proposition/evidence; Respondent proposition/evidence; undisputed facts; disputed facts; burden; vulnerability of each side; what the tribunal must decide; missing evidence.
Separate evidence from advocacy. Do not collapse allegations into facts.
10 — Session Closeout
At the end of a substantive session create an audit trail:
Date / Task / Matter / Working set used.
What was produced and filenames.
Material conclusions.
Sources materially relied upon.
Verification required.
Explicit lawyer decisions/instructions.
Open items: owner / next action / target date.
Recommend updates to Core chronology, Issue map, Witness map, Research log, Procedural calendar or Project Instructions.
Do not update source-of-truth documents unless explicitly instructed.

11. Rotina de 6 passos

1. Matter→2. Deliverable→3. Session Pack→4. Analyze→5. Verify→6. Closeout + DMS
Objetivo: não é usar Claude mais. É reduzir trabalho mecânico preservando rastreabilidade suficiente para defender de onde veio cada proposição material.
